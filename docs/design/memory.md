# 记忆设计（第一层：用户本人）

> 状态：首版。内核 `packages/core/src/memory.ts`，界面 设置 › 记忆 和对话里的「已记住」一行。
> 最接近的现成做法：ChatGPT 的「已保存的记忆」。模型自己判断要不要记，用户说「记住」时一定记；每条是一句短话。
> 2026-11-13 起照 Claude 的记忆页分两层（渐进式披露）：记忆按「条目」存，一个条目有名字、摘要、类别，下面若干条「详情」（就是原来的一句话）。系统提示里只放条目的名字和摘要，模型要用到时再用 `recall` 取详情；设置页列表一行一个条目，点进去才看到详情。

## 1. 范围

- 只在助理自己的对话里有记忆：会话角色是 `top`、模板是 `top`（或没有模板）、不在项目里（`hasMemory()`）。
- 项目经理、项目里的子任务、邮件分拣、子 Agent 都不读也不写。
- 每条记忆带 `owner`，现在只有 `'user'`。以后给常驻成员加记忆，只改这个字段（`SessionConfig.memoryId` 指向别的 owner）。

## 2. 记

工具说明只讲记忆是做什么用的：以后的对话里用得上、又不能从对话里直接看出来的事（他是谁、要怎么干活和回答、他工作上长期不变的事）；手上这件事的进度、一次性的步骤、找得回来的东西都不记；少而长久的几条比多记更有用；只写他说的，不加自己的话。

模型手里有三个工具：

| 工具 | 什么时候用 | 参数 |
|---|---|---|
| `remember` | 用户说「记住…」「以后都…」；或者说了关于本人、做事习惯、以后对话还用得上的事 | `text`（一条详情：不写主语的一句话，≤ 200 字）、`quote`（用户的原话）、`entry`（条目名字：已有的就加进去，没有就新建）、`summary`（新建时要给；已有的条目要改摘要时给）、`category`（新建时给）、`replaces`（换掉第几条详情） |
| `recall` | 要用到某个条目的详情时（只读，不画卡片，不算这一轮动过手） | `entry`（名字） |
| `forget` | 用户说「别记了」「忘掉…」 | `id`（详情的编号）、`quote` |

内核在存之前逐项核对，有一项不过就不存，把原因回给模型：

1. **原话只认用户亲手打的字**：在这条对话里 `kind` 为 user / steer、作者是用户的消息里找 `quote`；附件的正文、`<untrusted_data>` 里的内容、工具结果都不算。比对前去掉空格、标点，统一全半角和大小写。
2. **读过外来内容的那一轮更严**：这一轮读过文件、网页、邮件、插件结果，或者「查找对话记录」查回来过东西（`Session.actsOnOutsideContent`）。这时原话只能出自用户最新那条消息（含他运行中插的话）。另外有两道：
   - 记下的句子里，字对（相邻两个字）有一半以上要出现在他这条消息里（`outsideTurnOverlap` 0.5）。不够就退回，让模型用他的原话重写。
   - 句子里不在他消息里、却出现在这一轮外来内容里的字对，最多占五分之一（`outsideTurnForeign` 0.2），超过就拒。
3. **密钥类不记**：部署自己的密钥（`redact`）、`密码是…` 这类写法、身份证号、卡号、像随机串的长 token，按样子拦。
4. **敏感话题**：健康、宗教、政治等，用户没说「记住」就不存（按词拦）。
5. 同一句已经在记忆里就不再加一条。

替换：`remember` 带 `replaces`，新的一条存进去，旧的标 `replaced`（`replacedBy` 指向新的）。不会两条并存。换掉的那条在哪个条目，新的就进哪个（除非给了别的 `entry`）。

**条目**（2026-11-13 加）：
- 名字 ≤ 30 字，同一个人的记忆里不重名（比较时去空格标点、统一大小写）；摘要一句，≤ 120 字，不写主语。
- 名字和摘要没有自己的原话、每轮都进系统提示，所以和详情过同样几道：空、超长、像密钥就拒；健康宗教政治这类，他没说「记住」不存（`entryProblem`）。那一轮读过外来内容时，新名字和新摘要里不在他最新那条消息、也不在这个条目已有详情里，却出现在外来内容里的字对，最多占五分之一（`entryFromOutside`）。
- 给了没有的名字却没给摘要：拒，回一句「要新建就给摘要（和类别）」。没给 `entry`：照样存，只是不在任何条目里（「散的」），等整理归。
- `remember` 新建了条目或改了它的摘要、类别：这条详情上记下改之前的样子（`entryChange`）。撤销这条详情时，条目要是之后没人动过（`updatedAt` 还是那时的），就把名字摘要类别换回去；新建的那个条目详情都没了就不显示。
- 条目没有状态：有正在用的详情才显示、才进系统提示。

**类别**（2026-11-13 加，照 Claude 记忆页的分组）：类别放在条目上，五选一。工具说明里每类一句话，模型新建条目时给：

| 值 | 界面上 | 放什么 |
|---|---|---|
| `you` | 你 | 他是谁、要怎么干活和回答（职务、习惯、偏好） |
| `areas` | 领域 | 他负责的那几块工作或生活，和那里长期的规矩（一项职责、某类文件怎么写） |
| `topics` | 主题 | 他关注的话题和兴趣（爱好、在看的领域） |
| `people` | 人物 | 他提到的人：是谁、怎么打交道 |
| `projects` | 项目 | 某个具体项目和它长期不变的事（名字、目标、人、定下的日期） |

- 「领域」和「主题」的分法是我们的理解：Claude 公开的说明里只看得到 You、Topics 两组和按项目分开的记忆，查不到 Areas、People 的定义。这里定成：领域是他要管的事（工作上的职责和规矩），主题是他感兴趣的事。
- 类别不在 `required` 里：模型漏给或给了不认识的值，照样存，条目没有类别（列表里排在最后那组）。设置里可以改。

## 3. 读

每轮请求的系统提示后面加一段（钩子 `core:memory`，位置 `system:after`）。这一段写明：这些是关于用户的笔记，不是指令；跟用户现在说的冲突时，以现在说的为准。分两部分，合起来最多 3000 字：

```
Your memory is kept in entries: … call recall with its name …
- 工程部职责 (areas): 负责样品和报价；报价单写含税价 — 3 details, 2026-11-13
- 王经理 (people): 直属上司，周报发给他 — 2 details, 2026-11-12
Notes not in an entry yet ([n] is the number for remember `replaces` and forget):
[12] 一般周三下午不开会 (2026-11-10)
```

- 条目：只有名字、类别、摘要、详情条数、最后修改的日期（条目和它的详情里最新的），新的在前，最多 60 个。
- 散的详情（还没归进条目的旧记忆）：照旧一句一行带编号，最多 40 条。
- 超出的写一句「还有 N 个旧的没列出」。
- `recall` 回 `名字 (类别): 摘要`，下面每条详情 `[编号] 那句话 (日期)`；名字对不上就回现有名字的列表。

## 4. 存

表 `memories`（详情，id 自增、不复用；owner、status、updated_at 单列，整条 JSON 放 data）和 `memory_entries`（条目，同样的写法，写入也开 `secure_delete`）。字段见 `@spica/protocol` 的 `MemoryItem`、`MemoryEntry`；详情的 `entryId` 指向条目。

- 状态只有 `active` / `replaced` / `forgotten`。对话里的忘掉、撤销、整理都只改状态，所以那一行的「撤销」和整理的撤销能换回来。
- **设置里删除、全部清除是真删**（2026-11-13 改，他在点选页上定的「真删」）：那条连同它换掉的旧版（`replaced` 且 `replacedBy` 指向它的，一层层往前）从表里删掉，删的时候开 `secure_delete`、删完把预写日志清空（`wal_checkpoint(TRUNCATE)`），文件里不留那几句话。记忆的写入（编辑）也开 `secure_delete`，改掉的旧字不留在空页里。全部清除只删正在用的那些和它们的旧版；对话里忘掉的、撤销掉的不删，那几行的「撤销」照旧能用。
- 真删后只留出处：那几条是从哪条对话的哪条消息记下的（`meta` 表 `memory_deleted:<owner>`，只有 `会话 id#消息号`，没有字），整理不再从那条消息补记它。
- `undone`：这条是被对话里那一行的「撤销」（或整理的撤销、重新生成）撤掉的。界面靠它显示「已撤销」。
- 编号自增、不复用，删掉以后也不复用（旧对话里那一行的「撤销」不会落到别的条目上）。
- `sessionId` / `seq`：在哪条对话、出自他哪条消息；设置里自己加的没有。
- 删掉一条对话，从它记下的记忆还在。

## 5. 改

| 谁 | 做什么 | 内核 | AgentApi |
|---|---|---|---|
| 设置 › 记忆 | 列表（含已替换、已删除） | `memory.list({ all })` | `listMemories` |
| | 条目（有正在用的详情的） | `memory.entries()` | `listMemoryEntries` |
| | 添加（新条目：名字、摘要、类别、第一条详情；或往已有条目加一条详情） | `memory.addOwn(text, entry)`：空、超长、像密钥都拒，名字重了拒（`MemoryRefusal`，`field` 说是名字还是摘要） | `addMemory` |
| | 编辑详情 | `memory.edit()`：同上 | `editMemory` |
| | 编辑条目（名字、摘要、类别） | `memory.editEntry()`：同上 | `editMemoryEntry` |
| | 删除详情 | `memory.delete(id)`：真删，连同旧版；条目里最后一条，条目一起删 | `forgetMemory`（名字沿用） |
| | 删除条目 | `memory.deleteEntry(id)`：条目和它所有的详情（任何状态，连同旧版）真删 | `deleteMemoryEntry` |
| | 全部清除 | `memory.clear()`：所有条目和正在用的详情都真删，连同旧版 | `clearMemories` |
| | 启用记忆 | `memory.setEnabled()`；后台 `configure({ memory: { enabled } })`，启动配置 `BackendConfig.memory` | 设置补丁 |
| 对话里那一行 | 撤销 | `memory.undo()`：记下的删掉并标 `undone`；替换的删掉新的、旧的换回来；忘掉的恢复 | `undoMemory` |
| 重新生成 | 旧回答的改动跟着撤销 | `memory.revert(cards)`：见下 | `regenerate` |

**重新生成**（他定的「跟着撤销」）：点「重新生成」换掉一个回答时，先把那个旧回答里 `remember` / `forget` 做的改动按从后往前的顺序撤掉，再跑新的一版；新回答看到的系统提示里已经没有旧回答记下的那条，它自己再决定记不记。改动从那一轮工具调用记录的卡片里取（`ToolCallRecord.cards.memory`）。只撤「之后没人动过」的：条目还是卡片上的样子（`updatedAt`、状态都没变）。他已经点过撤销的、在设置里改过或删掉的、后来又被别的调用改过的，都不动；同一个回答先记下、又改掉或忘掉的那条，一并撤掉。被撤掉的记成 `undone`，以后整理不会再从那条消息补记它（新回答没记就是没记）。所以 `remember` / `forget` 不算「这一轮动过手」，只调过这两个工具的一轮可以重新生成；同一轮还调过别的可能产生改动的工具时，照旧不给。

关掉记忆：对话里不再放记忆，模型也看不到 `remember`、`forget` 两个工具；已存的不动。

## 6. 整理

最接近的现成做法：Anthropic 的 dreaming。在对话之外拿笔记对照原始记录：过时的换掉、重复的合并、不成立的删掉、漏记的补上，让放进系统提示的那一层保持小而准。知识页（wiki）那一层不做：第一层只有关于他本人的几十条短话。代码在 `memory-tidy.ts`。

- **读什么**：现有的条目和详情（每个条目一段：`## 名字 (类别): 摘要`，下面它的详情；再列散的），加上次整理之后他在助理对话里亲手打的字（`typedText`，每条带 `c<n>#<seq>` 编号和时间）。回答、工具结果和外来内容都不给模型看。最多读最近 30 条对话、4 万字，一条消息最多 1500 字。
- **模型只提议**：用默认模型发一次请求，要求只回 JSON：`rewritten`（他后来说法变了）、`forgotten`（他说不成立了、别记了）、`merged`（几条说的是一回事）、`added`（以后用得上却没记，一次最多 5 条）。
- **内核逐条核对**，不过就只丢那一条（记进 `refused`）：
  - 原话真在它点名的那条消息里；
  - 改写和删除的出处要晚于被改的那条；
  - 和 `remember` 同样的规矩（`noteProblem`：空、超 200 字、像密钥、没说「记住」的敏感话题）；那一轮读过外来内容时，同样要过两道拦；
  - 补记的不能是记过的（同一条消息）、删掉或撤销过的、和现有的几乎一样的；
  - 改写和合并不能丢掉旧笔记里的数字和带称呼的人名（王经理、李老师），除非他新说的话里自带同类的（「周会改到下午 3 点」可以换掉旧的 10 点）；
  - 合并要由被合并的几条组成、比它们加起来短，他撤销过的合并不再合并；
  - 每条记忆一次整理里只动一次。
- **请求**：一次最多 20 条改动、输出最多 4000 个 token；答案被截断时，截断前写完整的那几条照常核对。和对话里的模型调用一样先按最坏情况占用花费上限。
- **条目**：`added` 要给 `entry`（已有的名字，或新名字加 `summary`、`category`），改写留在原条目，合并只能合同一个条目里的（或都是散的）。另有两种不算改动的（不进改动列表、单条撤销不涉及、详情的「最后修改」不变）：
  - `grouped`：把散的详情归进条目（已有的或新建的），记在整理记录的 `grouped`。旧记忆就是这样迁移过来的：有散的就算上次之后没有新对话，也照样请求一次模型。
  - `summarized`：详情变了以后重写某个条目的摘要，改前的样子记在 `entries`。
  - 新建条目的名字摘要过和详情一样的规矩（同上第 2 节），一次整理里同一个新名字只建一个。
  - 「全部撤销」也把这两种撤回：归进去的回到散的（之后没再动过的），摘要换回去（条目之后没人动过的）。
- **一组改动**：一次整理存成一条记录（表 `memory_tidies`，`MemoryTidyRun`），改到的条目带 `tidyId`。替换和删除照旧只改状态。可以整组撤销，也可以单条撤销；只撤还成立的（之后又被改过、删过的不动）。
- **从哪读起**：起点（`meta` 表的 `memory_cursor:<owner>`）只在成功后前移到读过的最后一条；失败时记忆和起点都不动。关掉记忆再打开，起点挪到打开那一刻，关着时说的话不补记。整理到一半时应用被关或崩溃，下次打开时那次记成失败。
- **花费**：那次请求记进花费累计（全部对话），并存一条不属于任何对话的可追溯记录（`runtime:memory-tidy`），使用日志里看得到。实测 deepseek-flash 读 3 条对话 10 句话，约 800 个输入 token、500 到 900 个输出 token，一次约 0.006 到 0.009 元。读满上限（约 4 万输入 token、4000 输出 token）的最坏情况按目录价：deepseek-flash 约 0.11 元，deepseek-v4-pro 约 0.47 元，claude-sonnet-5-5 约 0.12 美元，claude-opus-5-5 约 0.24 美元。
- **什么时候跑**：设置 › 记忆 里「立即整理」随时可点（关着记忆或没配模型时不跑）。「自动整理」默认关；开着时由后台每 10 分钟看一次：没有对话在跑、距上次整理超过一天、上次之后有 5 条以上有新内容的助理对话，才跑。默认关的原因：整理用默认模型，会把他在别的服务商对话里说的话发给默认模型那一家（邮件默认关是同一个道理）。
- **接口**：`tidyMemories`（立刻返回，结果走事件 `memory.tidy`）、`listMemoryTidies`、`undoMemoryTidy(id, change?)`；设置补丁和启动配置 `memory.autoTidy`。

## 7. 事件和界面

- 每次改动都发 `memory.changed { card }`。模型调工具改的带 `callId`、发在那条对话上，同一张卡片也存进工具结果消息的 `meta.memoryCards[callId]`，重开对话照样画得出来。设置里的改动和撤销不带 `callId`，发在 sessionId `''` 上。
- 窗口收到任何一个 `memory.changed` 就重新取一次 `listMemories({ all: true })`。设置页和对话里的那一行都看这一份。
- 对话里：`remember` / `forget` 不进工具组，有卡片的画成一行：

| 卡片 | 那一行 |
|---|---|
| saved | 已记住：… 撤销 |
| replaced | 已更新：…（替换「旧的」） 撤销 |
| forgotten | 已忘记：… 撤销 |
| 撤销之后 | 已撤销：… |

  被拒的调用不画（模型的回答会说为什么）。改动后来在设置里被删（真删，条目不在了）、被新的替换，那一行只留文字，不再有「撤销」。整理的改动同样：涉及的那条被真删后，那一行只留文字。
- 设置 › 记忆：在「模型」后面单独一个标签。整页用设置共用的组和行（`settings/Group.tsx`），和 模型、插件、关于 一样：一组一个框，框里细线分行，按钮都是共用的 `.btn`（2026-11-13 按 `ui-rules.md` 重排）。
  - 第一组：「启用记忆」「自动整理」两个开关。
  - 「整理」一组：标题行右边「全部撤销」（有能撤的改动时）、「立即整理」（跑的时候是「整理中」）。框里第一行「最近一次」，灰字是时间和改动条数（没整理过是「—」）；下面每条改动占一行（新增 / 改写 / 合并 / 删除，被换掉的写在括号里），放不下的在行尾省略、悬停看全文，右端是「撤销」小按钮；撤过的写「已撤销：…」，不再有按钮。整理把旧记忆归进了条目的，灰字里多「归入 N 条」，改动下面每条一行「归入「条目名字」：那句话」（没有单条撤销，「全部撤销」把它们一起撤回；之后被删或挪走的不列）。「立即整理」被拒时，原因写在框下面。
  - 「已记住」一组（2026-11-13 照 Claude 记忆页重做：一行、二级页面、分类、条目）：标题行右边「添加」「全部清除」。下面按类别分组，顺序是 你、领域、主题、人物、项目，每组上面是类别名、各自一个框；空的组不显示。没有类别的条目和散的旧记忆排在最后一组，上面不写名字（不出「未分类」这种标签）。组内新的在上（条目按它和详情里最新的时间），一行一个条目：左边名字（占三成宽），中间灰色摘要（放不下省略，悬停看「名字：摘要」），右边时间，最右铅笔和垃圾桶两个不带框的图标（`icon-btn`）。散的旧记忆一行就是那句话。
  - 条目页（点一行；点铅笔直接是编辑）：设置右边换成这一页（和插件的详情页一样，不是弹出的一层）。左上「← 记忆」，回去后焦点在刚才那一行。标题是名字，右边「编辑」「删除」；下面「类别」「最后修改」「摘要」「详情」。详情是项目符号列表，标题行右边「添加」（往这个条目加一条）。编辑：名字、摘要两个输入框，「类别」五选一，「取消」「保存」；没改不能保存。
  - 详情页（点一条详情，或点散的那一行）：「← 条目名字」（散的是「← 记忆」），回去后焦点在刚才那条。标题是那句话，右边「编辑」「删除」；下面「最后修改」「出处」（来源对话，点了打开那条对话、滚到那条消息；对话删了或设置里自己加的就没有这一项）、「原话」（设置里加的没有）。出处和原话只在这一层，条目页不放。编辑：输入框，「取消」「保存」，保存后回到这一页。
  - 「添加」（列表上）：新建条目的页面，名字、摘要、类别、详情（第一条），四项里类别可以不选；保存或取消回到列表。被拒时原因写在框下面（「名字已被使用，未保存」「摘要为空，未保存」…）。
  - Esc：这一页本身不算一层（和插件详情页一样，Esc 关的是设置）；输入框算一层，Esc 先收输入框。
  - 删除：列表的垃圾桶和条目页的「删除」删整个条目，先确认（标题「删除「名字」？」，下面「N 条详情」）；详情页的「删除」删这一条（「删除这条记忆？」），删完回到条目页（最后一条就回列表）。都是真删。全部清除同样先确认，条数是条目和散的加起来。页面开着时那一条或那个条目没了（整理合并掉、对话里忘掉），回到列表。

## 8. 已知的洞

- 用户自己贴进消息里的原文，内核分不出哪部分是他写的，原文里的「请记住…」能通过核对。
- 夹带的话被模型换了说法、跟外来内容的字对不上时，第二道拦不住，只剩第一道限制它最多占一半。
- 敏感话题只按词拦，换个说法就拦不住。
- 记忆放进系统提示，模型不一定每次照做。
- 通过本程序的 MCP 服务（`spica_send`）发进来的消息也算用户亲手打的。
- 一条消息里说过两遍、被记下其中一遍的事，在设置里真删以后，整理可能从另一条消息再补记（只挡被删那条的出处）。
- 在设置里真删的，对话记录里那次工具调用的参数和那一行的文字还在（对话本身没删）；整理记录里那次改动的文字也还在。
- 整理：他贴进消息里的原文同样能当出处（和记下时一样分不出）。
- 整理：一条消息里说了两件事、其中一件已经记过，另一件不会被补记（同一条消息记过就不再补）。
- 整理：改写可能丢掉旧笔记里的细节。数字和带称呼的人名由内核拦；别的（地点、对象）只靠提示里那句「没改的细节留着」。
- 条目：名字和摘要是模型写的，只过「空、超长、密钥、敏感话题、外来内容」几道，内核不核对摘要说的和详情对不对得上。
- 条目：系统提示里看不到详情，模型不 `recall` 就可能重复记同一件事（同一句话内核会拦，换了说法拦不住）。
- 条目：设置里不能把一条详情挪到别的条目；整理归错了，只能整组撤销，或删掉重新加。
- 整理：最多读最近 30 条对话、4 万字；更早的这次读不到，起点前移后以后也不再读。

## 9. 对照和演示脚本

`packages/core/scripts/` 下三份，都要 `.env.local` 里的 DeepSeek key：

- `demo-memory.ts`：8 段演示对话，写成 Markdown。
- `keyword-memory.ts`：30 句话分「给 / 不给关键词提示」两组各跑几遍，看记得准不准。结论：关键词提示没有用，只用来拦密钥这类。
- `outside-turn-memory.ts`：每句话前面加「先读一个文件」，看读过外来内容那一轮的两道核对会不会误拒。
- `tidy-memory.ts`：用本机假网关造两条对话（它不调记忆工具），按「先说 A、后来改成 B」「同一件事说了两次」「中途提到但没记」放好笔记，再用 deepseek-flash 整理一次，打印前后和花费；给了目录就把整理前后的数据库各存一份。
- `entry-memory.ts`：六句话各开一条新对话（其中三句该进同一个条目），看条目、摘要、类别；再开一条问要用到详情的事，看会不会 `recall`；最后加两条散的，整理一次看归进哪个条目。
- `writing-memory.ts`：36 句（含 6 句一次性任务状态），每句一条新对话，看记了几条、写成什么样。改「记下」工具的说明和系统提示前后各跑一遍对照。
