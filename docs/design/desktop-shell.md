# 桌面外壳设计（`apps/desktop`）

> 状态：U1、U2、U3 完成，都在真内核上实测过（DeepSeek）：逐字流出、提问卡、插话、两个子任务并行再汇总、关掉重开都还在（2026-11-09）。
> 需求来源：立项书「定位」「界面」「数据与外壳」「硬环境约束」「首版验收」；作者的界面禁区（不在仓库里）。

## 1. 布局与区域

```
┌ 左侧栏 264px（通到窗口顶） ┬ 标题栏：当前会话标题（子会话前面带「项目 ›」）………………………… [详情开关][系统按钮] ┐
│ [Spica 横标]     [侧栏开关] ├──────────────────────────────┬──────────────────┬────────────────────────────┤
│ [ 对话 | 项目 ]             │  对话流（最宽 760px，右栏顶着往左）  │ 详情栏 300px     │ 预览栏 640px（左边可拖）    │
│ 新对话 / 收件箱             │  ……                         │ 类型 / 属于      │ 文件名 [预览方式][最大化]   │
│ 对话：顶层会话；项目：项目经理 │                            │ 工具调用         │ [打开所在文件夹][复制路径]  │
│   └ 子任务（层数不限）      │  输入框                      │ 文件 / 花费      │ [用系统程序打开][关闭预览]  │
│ 设置                        │                              │                  │ 文件内容（贴窗口最右）      │
└─────────────────────────────┴──────────────────────────────┴──────────────────┴────────────────────────────┘
```

右边是两个各自独立的栏（他 2026-11-12 的原话「打开的预览和信息栏是两个独立的右侧栏，信息栏单独设置一个按钮在顶部，且信息栏无法拉伸宽度也没有expand按钮」）：

- **预览栏**永远贴着窗口最右边（他 2026-11-12 选「够宽时并排，预览在最右」）：点文件卡、回答里的路径、详情里的文件、插件页的 `openFile` 时打开，右上角 × 关掉（`关闭预览`）。标题栏最右边的栏位图标（右边一栏的样子）专管预览（他：「详情栏要多加一个独立于右侧栏位的按钮，右侧栏位按钮管所有的预览右侧窗」；以后预览有多栏也归它；没有快捷键，留给 main 那边统一加）：开着时点它收起（等于点 ×）；收起后点它重新打开最后关掉的那个文件（悬停「预览：文件名」；开着时悬停「预览」）；这次启动还没预览过任何东西时它变灰，悬停「没有打开的预览：点对话里的文件打开」。打开着就在，不存开关；左边能拖宽（宽度存进设置），标题行里有「最大化」。
- **详情栏**在对话和预览之间（没开预览时就贴着窗口右边）：标题栏右上角它自己的按钮（列表图标，悬停「详情（Ctrl+Alt+B）」，在预览按钮左边）和 Ctrl+Alt+B 只管它，不管预览；固定 300px，没有拖动的边，没有「最大化」。插件的面板页（`placement: panel`）还是它顶上的标签（「详情 / Quick note」，他选「先留信息栏」）。
- 两个可以同时开着，各开各的、各关各的。窗口够宽时四样并排。**详情栏比较特殊**（他 2026-11-12：「详情栏比较特殊，不满足时直接消失而不是遮盖」）：放不下时直接不显示，不被预览盖住、也不浮到窗口上面（「被收起的栏点开关时浮出来」那条老规矩只对左侧栏和预览，不对详情）；放得下了自己回来，开关一直记着。放不下时标题栏的「详情」按钮还在、变灰不能按（`aria-disabled`，和 `.btn` 一样的灰），Ctrl+Alt+B 也不起作用；悬停说为什么：开着预览时「放不下详情：把预览拖窄或关掉，或把窗口拉宽」，没开预览时「窗口太窄，放不下详情」。标题栏横贯整个窗口（见下面「顶上一行」），预览盖住对话区时它和这个按钮也不会被盖住。

- 外框对标 Claude Desktop（他的原话「外框区域要划分干净」「左侧栏的范围是到最顶部的」「参考claude」）：左侧栏通到窗口最顶，左上角是 Spica 横标、右边是收起侧栏的按钮；标题栏只盖主窗和详情，底下一条横线从侧栏边拉到窗口最右（系统按钮区高度少 1px，线在按钮下面也不断）；三栏之间是到底的竖线，交点直角。侧栏收起时标题栏最左边只留展开按钮（不放花标），下面是一列图标；指针停在展开按钮上（停 100 毫秒）会把侧栏临时浮出来，移进侧栏里保持不收，离开 400 毫秒后收回；停在图标栏的图标上不浮出，点图标直接去对应的页面。浮出时再点展开按钮就是真的展开（放得下就固定，放不下就留着不自己收回）；用按钮或 Ctrl+B 打开的不会自己收回。
- 标题栏是自画的（`titleBarStyle: 'hidden'` + Windows 的 `titleBarOverlay`），系统的最小化/最大化/关闭按钮由 Windows 画，但它们的底色是透明的（`CAPTION_BACK`），按钮底下露出的是页面自己：标题栏、对话框遮罩、开机动画都和界面一起出现、一起变；Windows 只画三个符号和指针停上去时的高亮。符号的颜色由页面告诉主进程（`ui/dim.ts` 的 `watchCover`：开机动画用动画的字色，遮罩和看图时按遮罩压暗，其余用次要文字色，`shared/skin.ts` 的 `captionSymbol`），这一下是直接换、不渐变。右侧用 CSS `env(titlebar-area-*)` 给系统按钮留位置。
- **对话区的两个宽度和让位顺序**（`shell/layout.ts`，规则和表格式测试都在那里；他 2026-11-12 的原话「主页面有两个宽度设置，在第一个宽度之前会被一直挤压，过了第一个宽度后，右侧栏遮盖主页内容直到最小尺寸」「任何位置修改宽度不满足主页第"0"宽度时，预览最先被隐藏」「详情栏比较特殊，不满足时直接消失而不是遮盖」）。440px：对话区最多挤到这么窄，内容跟着重新排版；侧栏宁可收起也不让对话比这窄，详情只在对话还有 440、预览按它的宽度都放得下时才在（老规矩「窗口变窄时不挤对话」）。160px：过了 440，预览不再挤对话，而是盖在对话区右边那部分上面：对话区保持 440 的排版不动、右边被切掉（像他给的 Claude 截图），直到只露出 160，再往左就拖不动了。160 是照参考图定的（图里露出约 175 像素、按字号算约 115px，取稍宽一点）：还能看到每条消息开头几个字和输入框左边的「+」，是哪条对话看标题栏。交界就是预览自己的左边线，没加阴影或压暗。被盖住时点对话区露出的部分什么都不发生，输入框被盖住的右半边（发送按钮）要自己把预览拖窄或关掉，回车照常发送。窗口变窄（或把哪一栏拖宽）时，最终顺序：**挤对话到 440 → 详情消失 → 再挤对话到 440 → 盖对话到只露 160 → 预览缩到 320 → 预览收起 → 侧栏缩、收**。详情在对话挤到 440 之后才走、不更早：对话区有多少空就占多少，没有别的宽度可以拿来当「更早」的那个点。他说的第 0 个宽度就是这个 160：保不住它时预览最先收起，侧栏在它后面。默认宽度（侧栏 264、预览 640）下的分界：1644 以上四样并排（对话 ≥ 440）；1643 详情消失；1344 对话又到 440；1064 对话只露 160；744 预览到 320；743 预览收起（侧栏还在）；639 侧栏收起（之后预览又放得下，到 531 再收）。1280 宽、三样都开：侧栏 264 + 对话露 376（盖住 64）+ 预览 640，详情不在。侧栏收起后留的那一列图标（52px）也算在里面。「最大化」照旧盖住整个对话区。被收起的左侧栏点开关、窗口太窄时点文件，会浮在主窗上面（**不压暗**窗口，Esc 或点面板外任何地方关，那一下点击照常生效），不改你保存的开关状态；宽度够了自动回到并排。窗口本身最小 480×360（`main/index.ts`）没改。
- **顶上一行**（他：「顶部标题栏是固定一体的不要区分(详情的标题不要到标题栏上)」，照他在 Claude 上画的分区 `out/ref/panels-1-claude-zones.webp`）：侧栏右边是一整条标题栏，横贯对话区、详情栏、预览栏，不被各栏切开；里面只有对话的名字、右端的「详情」按钮和预览按钮（照 Claude 标题栏那一排：间距 2，预览的在最右），最右给 Windows 的最小化 / 最大化 / 关闭留位置（`env(titlebar-area-*)`）；整条是窗口的拖动区。高 40（`--spica-titlebar-h`），底下一条线（`--spica-divider`），底色 `--spica-chrome`，左内边距 16。详情栏、预览栏都在这条下面，各自的第一行才是它们的标题行（「详情」/「详情 · Quick note」标签行 / 预览的文件名和展开、关闭等按钮），共用一处写法（`.panel-head`）：高 40、左 16 右 8，在栏自己的底色上、不另画线，图标按钮是 `.icon-btn`（30×30，间距 2）。侧栏的品牌行没动（左 14，是侧栏自己的事）。
- **底色**（他：「信息栏和主页底色一致，中间只有一个分割线」）：详情栏和预览栏都用对话区的底色（`--spica-bg`），和对话区之间、两栏之间只有一条到底的竖线（`.panel-right.is-docked` 的左边线）。预览栏照 Claude 图里的关系也是同一个底色（它里面看 PDF 等时的底色是查看器自己的）。侧栏和标题栏仍是 `--spica-chrome`。侧栏底部账号那一行上面一条横线（照 Claude 左下角），收起后的图标列也有。
- **内容列被右侧栏顶着往左**（他：「主窗口右边有空间的时候按照右侧所有空间居中摆放」「先压缩左侧空间，再开始变更宽度」「右边压着左边直到左边贴边」，参考图 `out/ref/centre-pushed-left.webp`、`out/ref/centre-squeezed.webp`）：对话的内容列（消息、输入框连同下面那行、排队的消息、运行提示条、「当前为演示数据」、新对话页的问候、回到底部按钮；最宽 760，`COLUMN_WIDTH`）平时放在侧栏（或图标列）右边到窗口右边这整块的中间，当右侧栏不存在。右侧栏开着、但左边缘减 24 还没碰到列的右边时，列一动不动；碰到了就顶着列往左走，列保持满宽，左边的空白越来越小；列贴到对话区左边（留 24）之后才变窄，到 440 之后照旧由预览盖住、露出至少 160，详情栏放不下就消失。没有「窗口中线」这条线（试过，他看了说右边没东西时也往窗口中线拉很奇怪）。算法在 `shell/layout.ts` 的 `centreShift`（表格式测试在 `layout.test.ts`），结果作为 `--centre-shift` 放在 `.main` 上，各处按它平移（新对话页的问候和演示那行字用两边不等的内边距）；拖动时跟着实时变。预览盖住对话时按对话区本身（440 的排版）算，那时列占满对话区，没有可挪的。消息区和收件箱的滚动条位置两边都留（`scrollbar-gutter: stable both-edges`），不然消息列会比输入框偏左半个滚动条宽。不在对话页时（收件箱、插件页）右侧栏不算，收件箱的列在对话区中间。
- **详情栏里**：每组是组标题（小字、淡色）接内容，组和组之间一条细线、上下各 12；行高统一（工具调用、文件、项目动态的每行上下各 4）；名目在左，时长、金额、文件所在文件夹在右，右边缘对齐成一列；文件那一行先截文件夹、文件夹截完才截文件名，都是省略号。
- **主页的详情栏**：主页就是还没打开任何对话的空页（全新安装第一次打开、点「新对话」，以及每次完全关闭后再启动停的那一页，见第 6 节「启动时停在哪」）。以前还算上「每次打开 Spica 时自动进的助理主对话」（他 2026-11-10 定「两种都算」），主对话已经删掉，那一半不再有。主页上详情栏默认收起，在那里点开只管这一次，不改对话里记着的开关。别的对话按上次开关来（`panels.right`，重启也记得；这个字段名是右边只有一栏时起的，现在只管详情栏）。预览栏没有这条：在哪里点文件都打开。
- **拖动调宽**：左栏右边、预览栏左边可以拖（指针变双箭头，悬停出一条细线；双击恢复，聚焦后方向键也能调），宽度存进设置（`panelWidths.left`、`panelWidths.preview`）。左栏 200–440；预览栏最窄 320、默认 640，最宽拖到对话只露 160 为止；不松手时就照最终结果实时变（他：「拖动不松手时就要实时变换最终的显示结果，不要松手了才跳变」）：对话被挤、详情消失、预览盖住对话都跟着指针走，松手时什么都不再动（以前详情要等松手才按新宽度判断，所以松手一跳）；窗口拉窄时本来就是实时的；存的是预览自己的像素宽度，和对话被挤还是被盖无关，窗口放不下时按上面的规则让，存的值不改。详情栏固定 300，没有能拖的边（以前右边一栏时存的 `panelWidths.right` 还留在设置里，没人读，给旧版本留着）。窗口变窄时先挤、再盖、预览再缩到最窄（`shell/layout.ts` 的 `panelWidths`：预览往左伸过多少是 `cover`，详情还露多少是 `infoShown`）。
- 快捷键：Ctrl+B 侧栏，Ctrl+Alt+B 详情栏（放不下详情时不起作用），Esc 一次收最上面一层（见第 1 节末「Esc 先收最上面一层」）。预览栏盖住整个对话区（Ctrl+Shift+\）的「最大化」按钮在预览标题行里、文件名后面；只有预览栏有，详情栏和标签行里都没有，标题栏里也没有（`ui/MaxButton.tsx`）。盖住整个对话区时详情栏也在它下面，还原后照旧。
- 「对话」「项目」两个标签在品牌行下面、「新对话」上面。侧栏收起后的图标栏在同一位置留一段同高的空位，所以「新对话」「收件箱」「设置」在收起、展开、悬停滑出三种状态下高度不变。
- 左下角是账号那一行（2026-11-12，他给的参考是 Claude 桌面端左下角）：左边圆形色块里是账号的第一个字（和没有图标的插件同一套「名字第一个字的色块」，`ui/badge.ts`；颜色按账号固定），接着是账号（太长在末尾截断，截断时悬停看完整的），最右边一个齿轮图标按钮（悬停「设置」，点了开关设置，和原来的「设置」一行一样）。点账号在这一行上方弹出菜单（照 Claude 左下角，用现成的 `ui/ContextMenu`，左边对齐，宽度不小于这一行）：最上面一行是账号全名（不能点，账号长被截断时在这里看全），下面「设置」（打开设置，停在上次的分区）和「模型设定」（停在 模型），前面各有设置左栏里同一个图标（齿轮、模型），16 大，和文字同色（悬停时一起变），和文字隔 10，往下挪 0.1em 和中文字形对上中线（中文字形在行盒里偏下，盒子居中时图标看着高 1.5px；等菜单有了文字前的图标参数，文字单独一层用 text-box: trim-both cap alphabetic 对齐，就不用挪），和设置左栏一样（图标用菜单项的 `icon` 参数，`ui/ContextMenu.tsx`；原来借 `after` 加一条样式排到文字前面，换成参数后逐像素一样）；再点一次账号关掉。键盘：账号这一块能聚焦，回车 / 空格开菜单，焦点在第一项，Tab 走到下一项，回车 / 空格选，上下方向键在能选的项之间走（到头绕回），回车选中，Esc 收菜单；这三样是共用菜单组件的，所有菜单都有。语言设置目前没有（界面文字都写死在代码里，没有多语言），菜单里先不放「语言」。原来单独一行的「设置」并进这一行，行高不变（34）。参考图里的套餐名和小箭头没有对应的东西，不做；不做下拉菜单。取不到账号（空）时这一行回到原来的「设置」（齿轮加字），不出空色块。收起成图标栏时只留齿轮（账号在悬停滑出的侧栏里看得到），所以三种状态下齿轮的高度一样。另一种摆法（齿轮后面留「设置」两个字）做在 `Sidebar.tsx` 的 `SETTINGS_WORD`，等他挑。
- 左侧栏行首对齐小标题（不给箭头留空位），每深一层缩一格；展开箭头紧跟名字，只在有子项时出现，是单独的按钮（名字上按左右方向键也能收起、展开）；行上其余位置点了都是打开这条对话。
- 左侧栏是会话树：「对话」放和助理的对话，「项目」放项目经理；任何会话开出的子任务都挂在它下面，层数不限。每行行尾只有一个状态位，一次只显示最要紧的一个：黄点（等你回答、确认）> 红点（出错、中断）> 进度环（运行中）> 蓝点（子任务已完成还没打开过）> 排队中 > 已停止。浅色皮肤里黄点用亮黄加一圈细边（警告色在浅底上是棕色，是给文字用的）；「对话」「项目」标签上和侧栏开关上都不放蓝点；空闲和已完成并打开过的不显示，这一行另外还有的情况写在悬停提示里。项目那一行是项目本身，不是一条对话：状态位一直留空，不显示自己的状态，也不汇总下面的；项目里的情况看它下面的行（下面有在跑的或等你的，项目会自己展开）。带子任务的对话收起时，取它自己和下面所有子任务里最要紧的那个，不写字也不写数量，悬停看「1 个待处理 · 2 个运行中 · 1 个排队中」。完成了还没打开过的子任务记在设置的 `doneNews` 里（`shell/row-status.ts`），打开就移出；只记应用开着时看到它完成的，所以升级前已经完成的不会亮。下面有东西在跑、或者正打开着其中一个时，默认展开。
- 打开时先播品牌包的开机画面（`SpicaSplash`），三栏在它底下同时就绪；会话列表读完就收尾淡出。完整版（每天第一次打开）的加载段至少播 `SPLASH_LOADING_AT_LEAST_MS`（10 秒减去品牌收尾 `SPLASH_FINISH_AFTER`，约 4.9 秒），再接收尾，合计约 10 秒；加载慢就等加载完。他 2026-11-10 在公司全新安装上看到加载几乎瞬间完成、动画「闪过」后定的。只加最短时长，各段顺序和时长不动；点一下或按键照样跳过；其余时候的 1 秒短版不变（`shell/Root.tsx`）。截图脚本不播。
- 入口自问（立项书那句）：设置只有左下角一个入口（齿轮，旁边的账号弹出菜单，各项也是打开设置；另外只在「一个模型都没配」时，空对话页给一个「去设置模型」，直达同一页）；新对话只在左侧栏顶部；项目行点名字进项目经理的对话，点前面的箭头只展开收起，两个动作分开、互不误触；子会话的标题栏带「项目 ›」可以一步回到项目。

- **Esc 先收最上面一层**（他定的：「按 Esc 时，有滑出的面板或浮动层就先收最上面那一层，再按一次才停止运行」；`ui/escape.ts`，2026-11-13）：会浮出来的东西都在这一处登记成「层」（`useEscape(开着, 关掉)`），各组件不再自己接 Esc。按一次 Esc 只收最后打开的那一层；一层都没有时 Esc 才往下走（输入框里运行中就是停止）。层的先后按打开的先后；同一下一起打开的（弹窗和它里面的菜单）外层在下；收件箱 / 监控台 / 插件页这种占着主区域的永远在最下面（`under`），盖在它上面的先收。登记成层的：所有菜单（`ui/ContextMenu.tsx`）、所有对话框（`useModal`：设置弹窗、点 × 的询问框、各确认框、新建项目、看大图）、上下文占用的卡片、改名框、记忆编辑框、「手动输入模型」框、监控台里点开一行的详情、悬停或点开关滑出盖在窗口上的侧栏和浮出的预览、预览「最大化」盖住整个对话区时（Esc 还原到旁边）、收件箱 / 监控台 / 插件页占着主区域时（Esc 回对话）。不算层的（按 Esc 不收它）：停靠在旁边的侧栏、详情栏、预览栏，悬停提示和用量图的悬停卡（任何按键都会让悬停提示消失，Esc 不被它吃掉），对话区下面 8 秒自己消失的提示条，输入法正在选字时的 Esc。
  - 焦点：Esc 收掉一层后，焦点回到打开这一层之前所在的地方（只在焦点会落空、或落在打开它的按钮上时才挪）。所以在输入框里打字时点开模型菜单，Esc 收菜单后焦点回到输入框，再按一次 Esc 就停止运行；原来焦点落到页面上，第二下 Esc 什么都不做。
  - 悬停滑出的侧栏：按 Esc 收起后，鼠标还停在侧栏开关上也不会立刻又滑出来，离开开关再回来才会；按 Esc 时鼠标在侧栏别处的，下一次停在开关上照常滑出。
  - 没接上的：插件页、HTML 预览、Office 预览是 iframe，焦点在页面里面时 Esc 到不了外面（浏览器本来如此）；要接需要插件页把 Esc 转给宿主，这次没做。原生下拉框（`<select>`）展开着、取色框打开着时按 Esc 会怎样没验。
## 2. 进程与 IPC

```
渲染进程（界面） ──window.spica──► preload ──ipcMain──► 主进程（窗口、设置、监护）
                                                         │  MessagePort（@spica/core 的 connectBackend）
                                                         ▼
                                          内核进程（utilityProcess：Runtime + SQLite + 提取器 + 插件）
```

- 合同用 `@spica/protocol`：`AgentApi` 是命令，`CoreEvent` 是事件。外壳自己的东西（设置、开文件、更新、插件页）在 `src/shared/bridge.ts` 的 `DesktopBridge`。主进程只放行 `AgentApi` 的方法名。
- **内核在独立进程里**（`src/backend/entry.ts`，随主进程一起构建成 `out/main/backend.js`）：用内核的 `runUtilityEntry({ modules })`，把 `@spica/extract` 和外壳自己的扩展 `@spica/desktop-host` 在构建时链接进去（打包后没有 node_modules，不能按包名动态加载）。
- `@spica/desktop-host`（`src/backend/desktop-host.ts`）是外壳的后端扩展：调 `@spica/plugins` 的 `attachBackend`（全进程一个插件管理器，MCP 服务上的插件工具照旧），再挂四个方法：`plugins`（插件页，含共享盘 / 网址来源、检查更新、更新）、`setProviders`（设置页改了模型，不重启就生效）、`createSession`（新的顶层会话用默认模型）；`probeProvider`（测试连接）是内核自带的。
- **监护**（`src/main/backend/process.ts`）：内核进程意外退出，按 1、2、5 秒退避重启，1 分钟最多 5 次；重启期间的调用排队等候，窗口标题栏显示「后台正在恢复」；新进程 `restore()` 后界面重新拉会话，跑到一半的回答显示「（中断）」和「继续」。超过次数显示「后台反复出错，已经停下 [重试]」。正常退出先把窗口藏起来，再发 `shutdown`，10 秒不退就强杀（装了插件时收尾要 4.5 秒左右，慢机器更久）；主进程最多等 11 秒（`main/quit.ts`）。
- **界面进程没了**（`src/main/page-recovery.ts`，2026-11-12）：renderer 被结束、崩溃或内存不足退出时，主进程记一行（原因、退出码），立刻重新加载页面，回到原来打开的对话（主进程记着当前对话，新页面从 `getShellState().reopen` 读一次，不放开机动画）；一分钟内第三次不再自动重试，弹应用自己画的小窗口「界面出错」[退出 Spica] [重新加载]（主按钮，初始焦点，回车）。发给窗口的消息都走 `sendToWindow`，页面不在就不发，不再刷「Render frame was disposed」。GPU 进程没了也记一行；改用软件渲染还没做。每次页面加载（启动和上面的重新加载）还记一行「page drawn」，带开始加载、加载完、准备显示、第一次显示的时刻；窗口在屏幕上 3 秒后主进程请页面画两帧、看 `#root` 有没有内容、截一张窗口内容看是不是全是一种颜色，不对就记一行「page not drawn」写明哪里不对；15 秒没加载完或加载失败也记一行（`src/main/page-watch.ts`）。只记日志，不重载、不弹东西。
- **自己画的小对话框窗口**（`src/main/app-dialog-window.ts`、`app-dialog.ts`，页面 `src/renderer/dialog.html` + `dialog/`，preload `src/preload/dialog.ts`，2026-11-12；他说「界面出错的对话框是windows默认样式的需要优化」）：主窗口页面画不出来时用的对话框。单独一个 `BrowserWindow`，自己的页面和界面进程（不加载主界面那一包代码），所以主窗口的页面没了它照样显示；无标题栏、不能调大小、主窗口的模态子窗口（任务栏不多一个图标），居中在主窗口上，跟主窗口同一缩放。样子照页面里的对话框（`ConfirmDialog`、`CloseDialog`）：标题、说明、可选的一组单选（默认选中哪项，答案里带选中的是哪项）、可选勾选框（在按钮上面，或和按钮同一行的左边）、靠右的按钮，主按钮在最后，可选右上角的 ×（点了等于没选，和窗口被关掉一样），宽度默认 400；颜色是主进程按当前皮肤算出的 token（`deriveTokens`）随文字一起传进去，字号、间距照 `styles.css` 写成数值（`dialog/dialog.css` 每条注明对应哪条规则）；圆角和阴影用 Windows 11 窗口自己的（8px，页面里是 14px；透明窗口能画 14px，但会丢掉系统阴影，GPU 出问题时也更不稳，没用）。回车点当前焦点的按钮（默认是主按钮），不绑 Esc；Alt+F4 关掉等于没选（「界面出错」里当作退出，和原来消息框的取消一样）。小窗口建不出来、页面加载失败、页面进程在回答前没了、5 秒内没画出来：日志记一行「dialog window: …; asking with the message box」，改用 Windows 消息框问同一个问题（兜底的兜底）。点 × 时页面不可用的兜底也用它（见「关闭窗口时」）。
- **窗口和任务栏**（`src/main/window-fit.ts`）：只记日志，不改窗口。第一次显示时记一行基线「window fits the work area (first show, …)」；之后在最大化、还原、最大化状态下大小变化、进入全屏、显示器变化（`display-metrics-changed` / `display-added` / `display-removed`）时，窗口（`getBounds`）有一边超出所在显示器的工作区（屏幕扣掉任务栏）超过 10 DIP，记一行「window past the work area (事件): window …, display …, work area …, scale …, 状态 (maximized …, full screen …); past it by left … top … right … bottom …」，同样的画面连续只记一次。10 DIP 是正常最大化时 Windows 让窗口边框伸出工作区的那一圈（125% 下量得 getBounds 为 -7,-7 2064x1120，工作区 0,0 2048x1104）加取整余量；任务栏约 48 DIP。起因：有一台电脑上最大化后窗口底部落在任务栏后面，在另一台上复现不出来，先记下来看是哪一步变的。
- 截图和测试用假后端（`src/main/backend/fake.ts`），`SPICA_BACKEND=fake|core` 可强制。

## 3. 事件到界面的映射

| 事件 | 界面 |
|---|---|
| `message`（user / steer） | 一条用户消息（插话带「插话」小标，虚线边） |
| `text.delta` | 逐字追加到当前回答的正文（Markdown 渲染） |
| `thinking.delta` | 「正在思考 / 思考过程」可折叠行，默认收起。夹在工具调用之间的思考并进那一组（见下一行）；只有思考、没有调用时是单独一行 |
| `tool.call` / `tool.start` / `tool.end` | 工具行：动词 + 对象（「读取文件 需求说明.docx」）+ 用时；连续几个合成一行概述（「Listed a folder, read 2 files」），点开看每个的结果。中间夹的思考也算进这一组（`chat/Conversation.tsx` 的 `segments`）：一串「思考、调用、思考、调用…」是一行概述，概述只数调用，点开按先后列出每段「思考过程」和每次调用，各自还能再点开；只有一次调用、前后带思考时也成一组；回答的正文、卡片、已记住那一行把组断开，正文不收进去。运行中：组的那一行写正在跑的那一步（Running … 加计时）；正在写的思考留在组下面单独一行「正在思考」，下一次调用来了才并进去。右侧详情栏「工具调用」只列调用，不变。流式时先到的 `tool.call` 是一行等待中的占位，这一轮写完的消息里没有这次调用（被长度上限截断、或换了 id 重发）时，收到消息就去掉它，不再一直转圈 |
| `confirm.request` / `confirm.resolved` | 确认卡：只写要确认的是什么，「拒绝 / 允许」 |
| `ask.request` / `ask.resolved` | 提问卡：选项按钮 + 自由回答 |
| `suggest.actions`（工具 `suggest_actions`） | 操作建议卡：点一条就把它对应的话发出去 |
| 回答里 `read_file / write_file / edit_file` 的 `path` | 回答末尾的文件卡（点开用系统默认程序打开）；右侧栏「文件」同源 |
| `status` / `queue` | 回答末尾的状态行：花标动效 + 本轮计时 + 阶段文案（排队中，前面还有 N 个 / 思考中 / 正在回复 / 正在读取文件 / 等你确认 / 等你回答）；结束后停 1.4 秒「已完成 · 用时」再收起 |
| `cost`（session）/ `status` | 侧栏状态标记、详情的花费 |
| `child.spawned` / `session.renamed` | 侧栏会话树刷新 / 改名 |
| `message`（relay / report，带 `ChildNoteMeta`） | 子会话卡片：「X 做完了，回报」「你在那边说」「那边定了」，点名字进那个子会话 |
| `run.end` | 重新取一次历史（`getMessages` + `getPending`）作准；测试保证流式结果与历史重建一致，不跳 |
| `error` / `budget.stop` | 对话里一行红底人话提示（401、429、余额、连不上等翻成中文，见 `humanError`）；内核标了 `retryable` 的（网络、5xx、429、超时）先不显示，这一轮最后以出错结束时才显示最后那一句，重试后成功或用户停止的不留字；命令失败（IPC 抛错）在主窗顶部弹提示，可关 |

- 内部消息 → 界面的规则全在 `store/transcript.ts`（纯函数，有测试）：一轮里的多条助手消息合成一段回答；工具结果第一行的取数时间不显示。
- 侧栏状态位（见第 1 节）：进度环 = 在跑；虚线圈 = 排队；黄点 = 等你回答 / 确认；红点 = 出错 / 中断；蓝点 = 子任务已完成没打开过；停止图标 = 已停止；空闲不显示。进度环、虚线圈、停止图标来自品牌包的状态图标。项目收起时数量在悬停提示里，展开时不重复。

## 4. 皮肤 token

- 一个皮肤只有两个输入：**底色**和**强调色**（`shared/skin.ts`）。其余 20 多个 token 全部推出来：侧栏底、卡片底、浮层底、输入框底、两档边线、悬停 / 按下、正文 / 次要 / 更淡三档字色、强调色做字时的可读版、强调色上的字色、浅强调底、选中色、危险 / 警告 / 成功及其浅底、遮罩、阴影。
- 明暗不靠开关，靠底色算：哪种字色在底色上对比度高就用哪种；底色是中灰时字色推到纯黑或纯白。测试锁住：正文 ≥ 4.5:1、次要字 ≥ 4.5:1、更淡字 ≥ 2.5:1、强调色文字 ≥ 3:1。
- 内置三个选项：跟随系统、浅色、深色。自定义皮肤：设置 › 外观 › 新建皮肤（从当前皮肤复制），改名称、底色、强调色，改动立即生效并自动保存；删除要确认「删除皮肤「X」？」。
- 渲染层把 token 写到 `:root` 的 CSS 变量；主进程同一套算法算窗口底色和系统按钮颜色，并把 `nativeTheme.themeSource` 设成皮肤的明暗，滚动条、取色器等原生部件跟着变。
- 深色按 Claude Desktop 的层次取值（不照抄资源）：底色暖中性灰 `#262624`，侧栏和标题栏比主区深一层，输入框和菜单浅一层，你写的消息再深一层，字是暖白；强调色仍是 Spica 蓝。浅色不动。
- 你写的消息：靠右、最宽 85%、无边框的填色块（`--spica-bubble`），像 Claude；插话保留虚线边。
- 花标长瓣用 `--spica-accent`，跟随强调色。
- 首帧不闪：`main.tsx` 先 `await getShellState()` 写好 token 再渲染，窗口 `ready-to-show` 才显示。

## 5. 缩放

- 整窗缩放用 Electron 的页面缩放（`webContents.setZoomFactor`），不用 CSS `zoom` / `transform`，所以弹窗、浮层、取色器的位置天然对得上。
- 档位：67 / 75 / 80 / 90 / 100 / 110 / 125 / 150 / 175 / 200%。
- Ctrl+滚轮、Ctrl+= / Ctrl+- / Ctrl+0：页面里拦下（`shell/zoomInput.ts`，滚轮一格一档，触控板小幅滚动攒够再算一档），交给主进程按档位改并保存；主进程的 `before-input-event` 和 `zoom-changed` 留作兜底。应用菜单已去掉，避免默认菜单的缩放快捷键另走一套。已在真窗口实测：滚轮上两格 125%、下一格 110%，Ctrl+= / - / 0 按档走，设置文件里跟着变。
- 缩放值存进设置，下次启动 `webPreferences.zoomFactor` 直接用；标题栏系统按钮的高度随缩放同步（40px × 缩放）。已在真窗口 150% 下截屏核对过系统按钮和自画标题栏对齐。

## 6. 设置存哪

- 「已达花费上限」「API 余额不足」[模型设置]，别的出错（如「模型接口超时，请稍后重试。」）没有按钮：`Transcript.error`，下一次运行开始时消失，和原来一样。
- 「回答到达长度上限，没有写完」[继续]：最后一条回答是被截断的那条、且没有在运行时出现；发了下一句（或按继续）就不再是最后一条，自然消失。
- 「上次运行已中断」[继续]：会话状态是 interrupted 时（重启后照样出现），按继续 = `resume`。
- 「同一步重复了 8 次，要继续吗」[继续]：`stopped` = `repeated` 时，按继续 = 发「继续」。
同时有几条就上下叠，顺序是 中断、重复、截断，出错最靠近输入框（实际最多两条）。切到别的对话再回来还在：提示由每个对话自己的记录（transcript / 会话状态）算出来，不另存。灰色的小字说明（轮数上限、代理互发消息上限）和「等待确认 [处理]」那几行没动，还在对话里。演示后端加了「超时」（普通出错）和「断电」（像中途退出，留下「上次运行已中断」）。

- **任务栏图标**：运行时把品牌 PNG 重新上色成单色花（深色任务栏白、浅色黑，无底），存成 `<userData>\icons	askbar-<内容哈希>.ico`（换一种颜色就是另一个文件；以后每片瓣单独配色也走这条路）。装好的版本里，任务栏按钮用的是和窗口同一个 AppUserModelID 的快捷方式的图标，不是窗口自己的图标，而且只在按钮出现时读一次（2026-11-10 在装好的测试副本上实测，见 `main/taskbar-icon.ts` 开头）。所以启动时和系统深浅变化时：把开始菜单和固定到任务栏里启动这个 exe 的快捷方式改指到这个 .ico，等约 3.5 秒（资源管理器要一会儿才注意到），再让窗口换一个临时 AppUserModelID 再换回来，按钮当场换成新图标，不会多出一个按钮、不闪。桌面快捷方式不改（桌面是壁纸，不是任务栏）；安装程序、exe、卸载条目里写死的图标用品牌的「白花黑边」。便携版没有快捷方式，按钮用窗口自己的图标。开发版用独立的 AppUserModelID（`dev.spica.desktop.dev`）；带 `SPICA_USER_DATA` 运行时不改快捷方式（`SPICA_SHORTCUT_ICONS=1` 才改，测试副本用）。安装版的 AppUserModelID 从打包时的 `extraMetadata.appUserModelId` 读（和 appId 一致），另起标识打的包（测试副本、以后的公司版）也能对上自己的快捷方式。

  - 为什么不用 electron-updater：它的 generic 源只认 HTTP，公司常用共享盘。这里自己读 electron-builder 生成的同一份 `latest.yml`，校验 sha512，再静默运行按用户安装的安装包（`--updated /S --force-run`），装完自动打开新版本。

- **公告**：`announcements.json` 形如 `{ "announcements": [ { "id": "…", "text": "…", "level": "info|warning", "link": "https://…", "start": "…", "end": "…" } ] }`。启动 3 秒后取一次、之后每 30 分钟一次；上次取到的存在设置里，下次一打开就先显示（不让人等）。显示在标题栏右侧的空白处，不遮挡、不挤动任何东西；点 ✕ 关掉的不再显示。
- **Electron fuses**（2026-11-10）：打包时翻掉两个开关，装好的版本带 `--inspect` / `--inspect-brk` 不开调试口，也不读 `NODE_OPTIONS`（两者都能让启动它的人在主进程里跑代码）；run-as-node 保留，插件的 Node server 靠它起。实测：装好的测试副本带 `--inspect=9231` 和 `NODE_OPTIONS=--inspect=9232` 启动，两个端口都连不上；示例插件 notes 的 server 照常「运行中」。安装版的自动化测试只用 Chromium 的 `--remote-debugging-port`（只到渲染层）。
- **子进程不弹窗**：外壳自己起的子进程（更新时运行安装包）一律 `windowsHide: true`；内核和插件的子进程由它们自己保证。
