# 桌面外壳设计（`apps/desktop`）

> 状态：U1、U2、U3 完成，都在真内核上实测过（DeepSeek）：逐字流出、提问卡、插话、两个子任务并行再汇总、关掉重开都还在（2026-11-09）。
> 需求来源：立项书「定位」「界面」「数据与外壳」「硬环境约束」「首版验收」；界面禁区 `~/.claude/hoshi-ui-bans.md`。

## 1. 布局与区域

```
┌ 左侧栏 264px（通到窗口顶） ┬ 标题栏：当前会话标题（子会话前面带「项目 ›」）……… [详情开关][系统按钮] ┐
│ [Spica 横标]     [侧栏开关] ├──────────────────────────────────────────┬──────────────────────────┤
│ 新对话                      │  对话流（最宽 760px，居中）              │ 右侧栏 300px（详情）       │
│ 对话：顶层会话              │  ……                                     │ 类型 / 属于 / 文件夹       │
│ 项目：项目经理              │                                          │ 工具调用                   │
│   └ 子任务（层数不限）      │  输入框                                  │ 文件 / 花费                │
│ 设置                        │                                          │                            │
└─────────────────────────────┴──────────────────────────────────────────┴────────────────────────────┘
```

- 外框对标 Claude Desktop（他的原话「外框区域要划分干净」「左侧栏的范围是到最顶部的」「参考claude」）：左侧栏通到窗口最顶，左上角是 Spica 横标、右边是收起侧栏的按钮；标题栏只盖主窗和详情，底下一条横线从侧栏边拉到窗口最右（系统按钮区高度少 1px，线在按钮下面也不断）；三栏之间是到底的竖线，交点直角。侧栏收起时标题栏最左边只留展开按钮（不放花标）；鼠标停在窗口左边缘（标题栏下面那条）会把侧栏临时浮出来，移开就收回，用按钮或 Ctrl+B 打开的不会自己收回。
- 标题栏是自画的（`titleBarStyle: 'hidden'` + Windows 的 `titleBarOverlay`），系统的最小化/最大化/关闭按钮由 Windows 画，颜色跟皮肤同步；右侧用 CSS `env(titlebar-area-*)` 给系统按钮留位置。
- **窗口变窄时不挤对话**：先收右侧栏，再收左侧栏（`shell/layout.ts`，主窗最窄 440px）。被收起的栏点开关时浮在主窗上面（**不压暗**窗口，Esc 或点面板外任何地方关，那一下点击照常生效），不改你保存的开关状态。宽度够了自动回到并排。
- **主页的右侧栏**（他 2026-11-10 定「两种都算」）：还没打开任何对话的空页（全新安装第一次打开、点「新对话」），以及每次打开 Spica 时自动进的那个对话（助理的主对话），直到你打开别的对话为止，都算主页。主页上右侧栏默认收起，在那里点开只管这一次，不改对话里记着的开关。别的对话按上次开关来（`panels.right`，重启也记得）。
- **拖动调宽**：左栏、右栏和主窗之间的边可以拖（指针变双箭头，悬停出一条细线；双击恢复，聚焦后方向键也能调），宽度存进设置。左栏 200–440、右栏 240–600；窗口变窄时两栏先按比例让位，连最窄都放不下才收起（`shell/layout.ts` 的 `panelWidths`）。
- 快捷键：Ctrl+B 侧栏，Ctrl+Alt+B 详情，Esc 关浮层 / 关设置。
- 左侧栏行首对齐小标题（不给箭头留空位），每深一层缩一格；展开箭头在行尾，只在有子项时出现。
- 左侧栏是会话树：「对话」放和助理的对话，「项目」放项目经理；任何会话开出的子任务都挂在它下面，层数不限。行尾是状态标记；收起时换成下面所有子任务的摘要（「1 个等你 · 2 个在跑」）。下面有东西在跑、或者正打开着其中一个时，默认展开。
- 打开时先播品牌包的开机画面（`SpicaSplash`），三栏在它底下同时就绪；会话列表读完就收尾淡出。完整版（每天第一次打开）的加载段至少播 `SPLASH_LOADING_AT_LEAST_MS`（10 秒减去品牌收尾 `SPLASH_FINISH_AFTER`，约 4.9 秒），再接收尾，合计约 10 秒；加载慢就等加载完。他 2026-11-10 在公司全新安装上看到加载几乎瞬间完成、动画「闪过」后定的。只加最短时长，各段顺序和时长不动；点一下或按键照样跳过；其余时候的 1 秒短版不变（`shell/Root.tsx`）。截图脚本不播。
- 入口自问（立项书那句）：设置只有左下角一个入口（另外只在「一个模型都没配」时，空对话页给一个「去设置模型」，直达同一页）；新对话只在左侧栏顶部；项目行点名字进项目经理的对话，点前面的箭头只展开收起，两个动作分开、互不误触；子会话的标题栏带「项目 ›」可以一步回到项目。

## 2. 进程与 IPC

```
渲染进程（界面） ──window.spica──► preload ──ipcMain──► 主进程（窗口、设置、监护）
                                                         │  MessagePort（@spica/core 的 connectBackend）
                                                         ▼
                                          内核进程（utilityProcess：Runtime + SQLite + 提取器 + 插件）
```

- 合同用 `@spica/protocol`：`AgentApi` 是命令，`CoreEvent` 是事件。外壳自己的东西（设置、开文件、更新、插件页）在 `src/shared/bridge.ts` 的 `DesktopBridge`。主进程只放行 `AgentApi` 的方法名。
- **内核在独立进程里**（`src/backend/entry.ts`，随主进程一起构建成 `out/main/backend.js`）：用内核的 `runUtilityEntry({ modules })`，把 `@spica/extract` 和外壳自己的扩展 `@spica/desktop-host` 在构建时链接进去（打包后没有 node_modules，不能按包名动态加载）。
- `@spica/desktop-host`（`src/backend/desktop-host.ts`）是外壳的后端扩展：调 `@spica/plugins` 的 `attachBackend`（全进程一个插件管理器，MCP 服务上的插件工具照旧），再挂四个方法：`plugins`（插件页，含共享盘 / 网址来源、检查更新、更新）、`setProviders`（设置页改了模型，不重启就生效）、`createSession`（新的顶层会话用默认模型）；`probeProvider`（测试连接）是内核自带的。
- **监护**（`src/main/backend/process.ts`）：内核进程意外退出，按 1、2、5 秒退避重启，1 分钟最多 5 次；重启期间的调用排队等候，窗口标题栏显示「后台正在恢复」；新进程 `restore()` 后界面重新拉会话，跑到一半的回答显示「（中断）」和「继续」。超过次数显示「后台反复出错，已经停下 [重试]」。正常退出发 `shutdown`，5 秒不退就强杀。
- 截图和测试用假后端（`src/main/backend/fake.ts`），`SPICA_BACKEND=fake|core` 可强制。

## 3. 事件到界面的映射

| 事件 | 界面 |
|---|---|
| `message`（user / steer） | 一条用户消息（插话带「插话」小标，虚线边） |
| `text.delta` | 逐字追加到当前回答的正文（Markdown 渲染） |
| `thinking.delta` | 「正在思考 / 思考过程」可折叠行，默认收起 |
| `tool.call` / `tool.start` / `tool.end` | 工具行：动词 + 对象（「读取文件 需求说明.docx」）+ 用时；连续几个合成一行「调用了 N 个工具」，点开看每个的结果 |
| `confirm.request` / `confirm.resolved` | 确认卡：只写要确认的是什么，「拒绝 / 允许」 |
| `ask.request` / `ask.resolved` | 提问卡：选项按钮 + 自由回答 |
| `suggest.actions`（工具 `suggest_actions`） | 操作建议卡：点一条就把它对应的话发出去 |
| 回答里 `read_file / write_file / edit_file` 的 `path` | 回答末尾的文件卡（点开用系统默认程序打开）；右侧栏「文件」同源 |
| `status` / `queue` | 回答末尾的状态行：花标动效 + 本轮计时 + 阶段文案（排队中，前面还有 N 个 / 思考中 / 正在回复 / 正在读取文件 / 等你确认 / 等你回答）；结束后停 1.4 秒「已完成 · 用时」再收起 |
| `cost`（session）/ `status` | 侧栏状态标记、详情的花费 |
| `child.spawned` / `session.renamed` | 侧栏会话树刷新 / 改名 |
| `message`（relay / report，带 `ChildNoteMeta`） | 子会话卡片：「X 做完了，回报」「你在那边说」「那边定了」，点名字进那个子会话 |
| `run.end` | 重新取一次历史（`getMessages` + `getPending`）作准；测试保证流式结果与历史重建一致，不跳 |
| `error` / `budget.stop` | 对话里一行红底人话提示（401、429、余额、连不上等翻成中文，见 `humanError`）；内核自己在重试的（`retryable`）不打扰；命令失败（IPC 抛错）在主窗顶部弹提示，可关 |

- 内部消息 → 界面的规则全在 `store/transcript.ts`（纯函数，有测试）：一轮里的多条助手消息合成一段回答；工具结果第一行的取数时间不显示。
- 侧栏状态标记：转圈 = 在跑；虚线圈 = 排队；琥珀点 = 等你；红点 = 出错 / 中断；绿勾 = 子任务完成；空闲不显示。项目收起时在行尾写「1 个等你 · 1 个在跑 · 1 个排队」，展开时不重复。

## 4. 皮肤 token

- 一个皮肤只有两个输入：**底色**和**强调色**（`shared/skin.ts`）。其余 20 多个 token 全部推出来：侧栏底、卡片底、浮层底、输入框底、两档边线、悬停 / 按下、正文 / 次要 / 更淡三档字色、强调色做字时的可读版、强调色上的字色、浅强调底、选中色、危险 / 警告 / 成功及其浅底、遮罩、阴影。
- 明暗不靠开关，靠底色算：哪种字色在底色上对比度高就用哪种；底色是中灰时字色推到纯黑或纯白。测试锁住：正文 ≥ 4.5:1、次要字 ≥ 4.5:1、更淡字 ≥ 2.5:1、强调色文字 ≥ 3:1。
- 内置三个选项：跟随系统、浅色、深色。自定义皮肤：设置 › 外观 › 新建皮肤（从当前皮肤复制），改名称、底色、强调色，改动立即生效并自动保存；删除要确认「删除皮肤「X」？」。
- 渲染层把 token 写到 `:root` 的 CSS 变量；主进程同一套算法算窗口底色和系统按钮颜色，并把 `nativeTheme.themeSource` 设成皮肤的明暗，滚动条、取色器等原生部件跟着变。
- 深色按 Claude Desktop 的层次取值（不照抄资源）：底色暖中性灰 `#262624`，侧栏和标题栏比主区深一层，输入框和菜单浅一层，你写的消息再深一层，字是暖白；强调色仍是 Spica 蓝。浅色不动。
- 你写的消息：靠右、最宽 85%、无边框的填色块（`--spica-bubble`），像 Claude；插话保留虚线边。
- 花标长瓣用 `--spica-accent`，跟随强调色。
- 首帧不闪：`main.tsx` 先 `await getShellState()` 写好 token 再渲染，窗口 `ready-to-show` 才显示。

## 5. 缩放

- 整窗缩放用 Electron 的页面缩放（`webContents.setZoomFactor`），不用 CSS `zoom` / `transform`，所以弹窗、浮层、取色器的位置天然对得上。
- 档位：67 / 75 / 80 / 90 / 100 / 110 / 125 / 150 / 175 / 200%。
- Ctrl+滚轮、Ctrl+= / Ctrl+- / Ctrl+0：页面里拦下（`shell/zoomInput.ts`，滚轮一格一档，触控板小幅滚动攒够再算一档），交给主进程按档位改并保存；主进程的 `before-input-event` 和 `zoom-changed` 留作兜底。应用菜单已去掉，避免默认菜单的缩放快捷键另走一套。已在真窗口实测：滚轮上两格 125%、下一格 110%，Ctrl+= / - / 0 按档走，设置文件里跟着变。
- 缩放值存进设置，下次启动 `webPreferences.zoomFactor` 直接用；标题栏系统按钮的高度随缩放同步（40px × 缩放）。已在真窗口 150% 下截屏核对过系统按钮和自画标题栏对齐。

## 6. 设置存哪

- `%APPDATA%\Spica\settings.json`（主进程读写，先写临时文件再改名，写坏了读到的是默认值）。渲染层不碰 `localStorage`。字段：`skin`、`customSkins`、`zoom`、`panels.left/right`、`panelWidths`、`pinnedProjects`（置顶的项目）、`network`、`localConnect` 等。**加设置项先给默认值**：开发版热更新时，旧主进程不发新字段，渲染层要能兜住（2026-11-10 出过一次空白页）。
- 设置分五页：常规（邮件、工作流、网络、使用日志、开发者）、外观（皮肤、缩放、开机动画）、模型、插件、关于（版本、更新源）。
- 网络：代理地址（空 = 用环境变量）、不走代理的地址（逗号隔开）、额外信任的证书文件（公司 TLS 检查）、使用 Windows 的证书（默认开）。启动时和每次改动经 `configure({ network })` 传给内核，下一个请求生效；页面显示「现在：经代理 … · 用 Windows 的证书」和读不了证书之类的问题。
- 连上来的脚本改模型设置（内核的 spica_save_model 等 MCP 工具，他 2026-11-10 定「不确认、改完醒目展示」）：内核经宿主方法 `models.list` / `models.save` / `models.setDefault` 调外壳（`main/providers/host-models.ts`，和设置页同一个存储、同样的校验，中文错误原样回给 Agent），存完推一次 configure、通知窗口重读模型列表（`ProvidersChanged`）；`ui.activeSession` 告诉内核窗口开着哪条对话。内核在主对话和开着的那条对话里各写一条带 `meta.settingsChange` 的备注，外壳画成「设置已改动」卡（`chat/SettingsChangeCard.tsx`）：谁改的、改了哪些项（新增列全部，修改只列改了的）、地址原样、Consumer Key 只末 4 位、密钥只写「新填 / 未改动」、保存前测试结果、是否经你确认，[在设置里查看]。卡留在记录里，重启后还在。三种样子（提示条 / 色头卡 / 大横幅）在等他挑，挑定前默认提示条。
- 开发者：「允许本机脚本连接 Spica」默认关。打开后内核进程里起 MCP over HTTP（只听 127.0.0.1，端口 47820，被占就随机），令牌写 `<userData>\mcp-token`（只本人可读），`<userData>\mcp-http.json` 写 `{ url, tokenFile, pid, startedAt }`（不含令牌），插件 skill 的安装脚本读它把 zip 装进正在运行的 Spica。关掉或退出时停服务、删 mcp-http.json；异常退出留下的下次启动删掉。
- 邮件：`mail.enabled`（**默认关**；打开时先弹框说明来信会发给哪个模型分拣，同意后记 `mail.consentedAt`；没有这个记录的「开」一律当关，传给内核的也是关）、`mail.intervalMinutes`（5 / 15 / 30 / 60 分钟，默认 5）、`mail.ignore.from / subject`（一行一条，包含这段文字或 /正则/ 就直接忽略，不交给模型）。`mailSeen` 记每个项目经理的对话上次被打开的时间，用来算「有新来信」。
- 工作流文件夹：`workflowsDir`，空 = `文档\Spica\workflows`（启动时建好）。
- 使用日志：常规页「使用日志」选项目（默认全部）和时间（全部 / 今天 / 最近 7 天 / 最近 30 天），点「导出…」选保存位置（默认 `文档\Spica\使用日志-日期.jsonl`），由内核进程直接写文件（内核 `exportUsageLog`，密钥和接口地址已去掉），完成后显示条数、路径和「在文件夹中显示」。
- 这些改了都不用重启：主进程调内核的 `configure(patch)`（邮件、工作流文件夹、模型都走它），正在跑的会话不受影响。
- 模型存 `%APPDATA%\Spica\providers.json`。三种表单：OpenAI 兼容（接口地址、API Key、模型）、Anthropic（API Key、接口地址可留默认、模型）、WSO2 网关（网关地址、取 token 地址、Consumer Key（Client ID）、Consumer Secret（Client Secret）、Scope 可选、模型；标签先写 WSO2 开发者门户里的叫法，每栏下面一句「从哪来、长什么样」：地址一般以 /v1 结尾不带 /chat/completions，取 token 地址以 /token 或 /oauth2/token 结尾，Key 和 Secret 在门户里应用的 Production Keys，模型照管理员给的原样填）；三种都要填**上下文上限**（这个模型一次最多能装多少 token，必填、正整数；内核认识的型号用 `knownContextWindow(kind, model)` 自动填上、可以改，换成不认识的型号时自动填的数会拿掉；手填的不动），经 `ProviderConfig.contextWindows: { [模型]: n }` 传给内核，改了马上生效。之前存的没有这一项，列表里写「还没填上下文上限，点开补上」，补上之前输入框不显示上下文环。强模型（可空）、同时请求数、每分钟请求数（空 = 不限）收在「更多选项」里，默认折叠，其中有填错的自动展开。
- 密钥（API Key / Client Secret）用 Electron `safeStorage`（Windows DPAPI，按当前用户加密，不需要管理员）存密文；主进程从不把密钥发回界面，界面只知道「已保存」。系统不能加密时拒绝保存并说明。
- 设置页左上角一个返回箭头（只有箭头，悬停「返回对话（Esc）」），和 Esc 一样回对话。
- 表单填一半离开（换标签、回对话、Esc、点别的模型）回来还在：模型表单（每个模型各一份）、代理、邮件忽略规则、插件安装位置、更新源。只放在窗口内存里不写盘（模型表单有密钥），关掉 Spica 就没了（`settings/drafts.ts`）。
- 「测试连接」走内核的 `probeProvider`（在内核进程里，一次极小请求、不进会话）：先显示内核给的中文原因（「取 token 失败：…」「调模型失败：…」），再说该查表单哪一项（`main/providers/real-tester.ts`）；成功时说你填的模型名，服务端的叫法放括号里。截图和测试用假测试器，不联网。
- 默认模型：第一次保存时如果还没有默认就设为默认，已有（包括开发用模型）就不抢；任何一行都能「设为默认」。

## 7. 第一次用（UX 复查后定的）

- 「新对话」只是清空主窗；发第一句话时才建会话，所以连点不会多出空会话。
- 没配模型时：空对话页写「还没有配置模型 [去设置模型]」；硬发消息会提示「还没有配置模型，先到 设置 › 模型 里添加一个」。
- 所有报错先翻成人话（`shared/errors.ts`，主进程和界面共用）；提示条换页面就清掉，8 秒后自动消失。
- 没打开对话时右侧详情是空的，不放一列「—」。
- 拿不准的 4 处做成了点选页，他 2026-11-10 定了：设置页加返回箭头（不写字）、高级项收进「更多选项」、填一半离开自动留草稿、配置模型时必须填上下文上限。
- 界面禁区逐条过：无 emoji；无下划线（设置页标签改成填色块）；不能点的都不像按钮（「默认」「插话」是纯文字）；空值是「—」或不显示；术语只在模型表单里用网关管理员给的字段名（API Key、Client ID 等）；同一件事一处（详情不再重复状态）；不闪不跳（窗口缩放、改尺寸时对话贴底）；确认框只写对象（「删除模型「X」？」）。「不让人干等」与开机画面的冲突放进点选页由他定。

## 8. 收件箱（邮件分到项目）

- 来信从邮件插件来（插件启用时自己登记为邮件来源，配置里不写工具名）。内核按间隔拉新信 → 分拣线程把每封信归到项目 / 新事务 / 不用管 → 归到项目的交给那个项目经理，它读信、用建议卡给下一步、需要回复只起草。**全程不发信。**
- 左栏「新对话」下面一行「收件箱」，右边的数字是待你确认的封数。点开在主窗：
  - 「待你确认」/「全部」两个标签；右上「每 5 分钟查一次 · 上次 21:18」和「现在查收」。
  - 每封信一张卡：发件人、时间、主题、预览一行；下面是结果（「归到 网站改版」「新事务：xxx」「不用管」，带色点的纯文字，不像按钮）、理由（模型给的中文理由；规则忽略写「按规则忽略」；按发件人记忆的写「这个发件人的信你以前放进过这个项目」或「上次你忽略过」）、把握（大 / 一般 / 小，只对模型的判断显示）。
  - 按钮：归到项目的是「采纳 / 忽略 / 改归属 / 去项目看」；新事务是「建成项目 / 忽略 / 改归属」（建成项目 = 打开新项目对话框、名字填好建议，建好后这封信改归到新项目）；不用管的是「采纳 / 改归属」。处理过的显示「已采纳 / 已忽略 / 你改的」，仍可改归属。
- 有新信交给项目经理后，左栏那个项目后面出现「有新来信」（纯文字），打开那个项目的对话就消失；在收件箱里采纳或忽略的不再算。
- 项目经理的对话里，内核发给它的英文指令不显示，换成一张「收到 3 封来信」的卡（发件人 + 主题，「去收件箱」）。项目动态里写「收到来信「主题」」。
- 内核的分拣线程是一个顶层会话（模板 `mail-triage`），不在左栏出现——邮件只在收件箱一处。
- 实现：`renderer/src/store/mail.ts`（listMail + mail.* 事件 + mailFeedback）、`shell/InboxView.tsx`、`shared/mail.ts`（结果和理由的中文）；假后端 `main/backend/fake-mail.ts` 有 6 封虚构的信和每次「现在查收」多一封。
- 真机走查（2026-11-09，内核 + Outlook 插件模拟模式 + DeepSeek）：建「网站改版」「办公室搬迁」两个项目，点「现在查收」→ 收件箱分好、两个项目都出「有新来信」；办公室搬迁的对话里是「收到 3 封来信」卡；采纳、改归属到另一个项目、改间隔、改忽略规则、重新读取工作流都不重启后台。

### 外来内容里夹带的指令（内核 guard）

- 确认卡按 `cause` 加一行为什么要确认：`untrusted_turn`「这一步是看了外来内容后要做的不可逆操作，需要你确认。」、`outside_link`「要打开的链接只出现在来信或网页里，你没点过。」、`sensitive_file`「要读的是密钥类文件。」；内核的英文 reason 不显示。
- 工具读回来的内容被标记（`meta.guard[callId]` / `guard.flagged`）时，工具行下面一行浅色字：「这封信 / 这个网页 / 这个文件里 / 插件返回的内容夹带了指令，已忽略」。交给项目经理的信（`meta.untrusted`）在「收到 N 封来信」卡里那封后面标；收件箱里那封信下面也标（从分拣线程的历史重建，加上实时的 `guard.flagged`）。文案都在 `chat/format.ts`。

## 8a. 对话里的东西（U8，2026-11-10）

- **输入框**（像 Claude，`chat/Composer.tsx`）：文字下面一排——左边「+」加附件（也能把文件拖进来；发出去后在你那条消息下面显示文件卡，文件正文不显示），新对话还能选工作文件夹；右边「每次确认 / 自动批准」（自动只放行工具声明的不可逆操作，守卫要求的仍然问你；自动执行的工具行标「自动批准」）、模型（不止一个时是菜单，从下一步起换；只有一个时是纯文字）、上下文环加百分比（模型的上下文上限还没填时不显示）、停止、发送。接内核的 `send(…, { attachments })`、`setSessionModel`、`setApprovalMode`、`session.updated`、`confirm.auto`。
- **回到最新**：圆钮挂在输入框上沿居中，输入框变高 / 有排队消息 / 缩放都跟着走，到底就不显示。
- **子任务在等你**：父对话状态行下面点名「「子Agent A…」在等你确认 [去处理]」。等子任务超时写「还在做，先不等了」，不再红字「没有成功」。
- **右栏预览**（`shell/FilePreview.tsx`、`main/preview.ts`）：点文件卡在右栏只读打开——PDF 用内置查看器，Markdown 渲染，文本 / 代码等宽带行号（GB18030 的中文也认），HTML 放进不许脚本的沙箱，图片；文本超过 512 KB 只显示前面并说明；别的格式说「还不能在这里预览」。「用系统程序打开」交给 Windows。PDF 和图片经 `spica-file://<令牌>` 读，只有你点开的那个文件拿得到。预览时右栏至少 520 宽（窗口允许时）。
- **项目右键菜单**：重命名（原地改名，空名字不改）、置顶 / 取消置顶（排最前、名字后面一个小图钉，记在外壳设置里）、删除（确认框写明「只删 Spica 里的这个项目和它的对话记录；项目文件夹和里面的文件不会动」）。接内核 `renameProject` / `deleteProject` 和 `session.deleted` / `project.deleted`。
- **插件页面**（`shell/PluginFrame.tsx`、`main/plugin-views.ts`）：插件在 `views/<id>.json` 里声明的页面。`placement: sidebar` 的在左栏「插件」下面一个入口，点开占主窗；`panel` 的是右栏顶部的标签（「详情 / Quick note」）。页面在沙箱 iframe（`allow-scripts allow-forms`，没有同源）里，文件只经 `spica-plugin://<插件>/<路径>` 向插件系统要（每次问 `pluginViewFile`），页面 CSP 只放本插件、不能联网。入口页先注入主题变量（`--spica-bg / surface / fg / muted / border / accent / danger / font / radius`）和 `window.spica` 桥：`callTool`（只能用这个页面清单里的工具；不可逆的先弹 Spica 的确认框）、`onEvent`（theme、plugin.changed）、`theme`、`openFile`（本插件的文件，在右栏预览）、`notify`。每个调用按发消息的 iframe 认插件。插件停用时入口消失，打开着的页面换成一句说明。
- **任务栏图标**：运行时把品牌 PNG 重新上色成单色花（深色任务栏白、浅色黑，无底），存成 `<userData>\icons	askbar-<内容哈希>.ico`（换一种颜色就是另一个文件；以后每片瓣单独配色也走这条路）。装好的版本里，任务栏按钮用的是和窗口同一个 AppUserModelID 的快捷方式的图标，不是窗口自己的图标，而且只在按钮出现时读一次（2026-11-10 在装好的测试副本上实测，见 `main/taskbar-icon.ts` 开头）。所以启动时和系统深浅变化时：把开始菜单和固定到任务栏里启动这个 exe 的快捷方式改指到这个 .ico，等约 3.5 秒（资源管理器要一会儿才注意到），再让窗口换一个临时 AppUserModelID 再换回来，按钮当场换成新图标，不会多出一个按钮、不闪。桌面快捷方式不改（桌面是壁纸，不是任务栏）；安装程序、exe、卸载条目里写死的图标用品牌的「白花黑边」。便携版没有快捷方式，按钮用窗口自己的图标。开发版用独立的 AppUserModelID（`dev.spica.desktop.dev`）；带 `SPICA_USER_DATA` 运行时不改快捷方式（`SPICA_SHORTCUT_ICONS=1` 才改，测试副本用）。安装版的 AppUserModelID 从打包时的 `extraMetadata.appUserModelId` 读（和 appId 一致），另起标识打的包（测试副本、以后的公司版）也能对上自己的快捷方式。

## 9. 打包、更新与公告

- **出包**：`npm run dist -w @spica/desktop`（electron-builder，配置 `apps/desktop/electron-builder.yml`），出到 `apps/desktop/release/`：
  - `Spica-Setup-<版本>.exe`：按用户安装（`perMachine: false`、`allowElevation: false`、`requestedExecutionLevel: asInvoker`），装到 `%LOCALAPPDATA%\Programs\Spica`，卸载信息写在 HKCU，**不需要管理员权限**；
  - `Spica-Portable-<版本>.exe`：便携版；
  - `latest.yml`：版本号、安装包文件名和 sha512，给更新用。预发布版本（如 `0.1.0-rc.1`）也写成这个文件名：配置里固定了 `channel: latest`，不固定的话 electron-builder 会按版本后缀写成 `rc.yml`，更新和发版流程都找不到。
- **改名打包（公司版）**：`apps/desktop/deploy.json`（不受版本控制）的 `app` 一节是唯一来源：`{ "app": { "name": "名字", "id": "com.example.app", "icon": "相对路径.ico（可选）", "font": "相对路径.ttf/.otf（可选）" } }`。不写或写 Spica 就是现在的 Spica，一处不变。检出 tag、放这一个文件、`npm run dist`，出来的就是这个名字的安装包，受版本控制的文件一个都不改。
  - `scripts/deploy.mjs` 读和校验（名字会成为文件夹名，不能有 `<>:"/\|?*`；改了名就必须换 id，否则会和 Spica 的安装混在一起）；出错就停，报中文原因。
  - `scripts/dist.mjs`（`npm run dist`）把 appId、productName、快捷方式名、安装包 / 便携版文件名（`名字-Setup-<版本>.exe`）、图标交给 electron-builder（命令行覆盖）。
  - `electron.vite.config.ts` 把 `{ name, id }` 编进主进程、预加载和界面（`__SPICA_APP__`，读法见 `src/shared/app-identity.ts`）；界面的字标由品牌的 `wordmarkForName(name, font?)` 在构建时生成（`__SPICA_WORDMARK__`，`src/renderer/src/app-wordmark.ts`），交给开机画面和侧栏横标；侧栏横标最宽 150px，名字长就整体缩小。自带的 Gelasio 只有拉丁字母，中文名要给 `font`。
  - 跟着名字走的：窗口标题、任务栏 AppUserModelID（= id）、数据文件夹 `%APPDATA%\名字`、`文档\名字`、界面上的 Spica 字样（输入框提示、关于、本机脚本连接、邮件同意、模型表单、新建项目、删除项目）、`mcp-http.json` 里的 `appName`。自我介绍（内核）、插件提示（插件系统）各自接 `appName`。
  - 不跟着变的：`@spica` 包名、`window.spica`、`spica_` 工具名、`--spica-*` 变量、`SPICA_` 环境变量、插件清单里的 spica 字段、`spica-file://`、`spica-plugin://`。
  - 2026-11-10 用虚构名字「Nova Desk」走过：开发版标题、开机字标、侧栏横标、输入框、关于都换了；`npm run dist` 出 `Nova Desk-Setup-0.1.0-rc.1.exe`、`Nova Desk-Portable-…`、`Nova Desk.exe`。
- **更新源**：一个共享盘文件夹或 http(s) 地址，里面放 `latest.yml` 和安装包（就是 `release/` 里那几个文件），公告也放这里（`announcements.json`）。
  - 默认是空的。公司打包时复制 `deploy.example.json` 为 `deploy.json`（已 .gitignore）填上自己的地址，就成了每台机器的默认值；用户也可以在 设置 › 关于 里改。仓库里只有示例，没有任何公司地址。
  - 为什么不用 electron-updater：它的 generic 源只认 HTTP，公司常用共享盘。这里自己读 electron-builder 生成的同一份 `latest.yml`，校验 sha512，再静默运行按用户安装的安装包（`--updated /S --force-run`），装完自动打开新版本。
  - 启动 10 秒后查一次，之后每 4 小时一次；有新版本就先下载校验，标题栏显示「新版本 x 已经下好 [重启并更新]」。便携版只提示「有新版本，请从更新源拿新的便携版」。
- **公告**：`announcements.json` 形如 `{ "announcements": [ { "id": "…", "text": "…", "level": "info|warning", "link": "https://…", "start": "…", "end": "…" } ] }`。启动 3 秒后取一次、之后每 30 分钟一次；上次取到的存在设置里，下次一打开就先显示（不让人等）。显示在标题栏右侧的空白处，不遮挡、不挤动任何东西；点 ✕ 关掉的不再显示。
- **子进程不弹窗**：外壳自己起的子进程（更新时运行安装包）一律 `windowsHide: true`；内核和插件的子进程由它们自己保证。
